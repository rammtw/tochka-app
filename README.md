# Точка — daily tracker

Личный ежедневный трекер задач, база знаний и отдельное хранилище паролей. React + TypeScript на клиенте, Express и SQLite на сервере. Все данные хранятся локально и сохраняются между перезапусками.

## Возможности

### Авторизация

- страница `/login` без регистрации;
- один локальный аккаунт;
- сессия в HttpOnly-cookie сроком на 7 дней;
- защита всех прикладных API и автоматический выход при истечении сессии.

**Данные для входа по умолчанию:**

```text
Логин:  admin
Пароль: Tochka!2026
```

### Задачи

- задачи на выбранный день с названием, временем и описанием;
- чекбокс выполнения, фильтры «Все / В работе / Готово»;
- создание, редактирование и удаление;
- переход по датам и наглядный дневной прогресс.

### База знаний

- документы с категориями и отдельной страницей просмотра `/wiki/:id`;
- Markdown: заголовки, списки, ссылки, код, цитаты, таблицы и списки задач;
- предпросмотр Markdown прямо в редакторе;
- поиск по названию, категории и содержимому;
- создание, редактирование и удаление документов.

### Хранилище паролей

- отдельный раздел с названием сервиса, логином, ссылкой, паролем и заметкой;
- поиск по сохранённым доступам;
- пароли скрыты по умолчанию, показываются и копируются по действию пользователя;
- AES-256-GCM для шифрования паролей в базе;
- API списка доступов никогда не возвращает значения паролей.

При обновлении со старой версии пароли из wiki автоматически переносятся в хранилище с пометкой «Перенесено из базы знаний».

## Быстрый старт

Требуется **Node.js 22.5 или новее** — SQLite используется через встроенный модуль `node:sqlite`, отдельная СУБД не нужна.

```bash
npm install
npm run dev
```

Откройте http://127.0.0.1:5173 и войдите с указанными выше credentials. API запускается на http://127.0.0.1:3001, Vite проксирует к нему `/api`.

### Production-режим

```bash
npm run build
npm start
```

Готовое приложение доступно на http://127.0.0.1:3001. Express раздаёт собранный React и API из одного процесса.

Перед сетевым развёртыванием обязательно замените стандартные credentials и включите HTTPS:

```bash
export AUTH_USERNAME="your-login"
export AUTH_PASSWORD="your-strong-password"
export COOKIE_SECURE="true" # только при HTTPS
npm start
```

## Данные и безопасность

По умолчанию создаются:

- `data/daily-tracker.sqlite` — база задач, wiki, доступов и сессий;
- `data/.encryption-key` — локальный ключ шифрования с правами `0600`.

Каталог `data/` исключён из Git. **Для восстановления зашифрованных паролей при переносе нужны и база, и ключ.** Для production задайте собственный ключ через переменную окружения:

```bash
export DATA_ENCRYPTION_KEY="$(openssl rand -hex 32)"
npm start
```

Ключ должен быть постоянным: после его смены старые пароли расшифровать невозможно. Дополнительно поддерживаются `PORT` (по умолчанию `3001`), `HOST` (`127.0.0.1`) и `DATA_DIR` (`data`).

Сессионный токен хранится в базе только как SHA-256-хеш, cookie имеет флаги HttpOnly и SameSite=Strict. Вход ограничен пятью неудачными попытками за 15 минут с одного IP. Счётчик хранится в SQLite и сохраняется после перезапуска; ответ `429` содержит заголовок `Retry-After`. Markdown отображается через `react-markdown` без выполнения встроенного HTML.

Это однопользовательское приложение. Для публичного развёртывания дополнительно нужны HTTPS, резервное копирование и мониторинг. Маскирование паролей в интерфейсе не заменяет серверную авторизацию.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Клиент и сервер с автоматической перезагрузкой |
| `npm run build` | Проверка TypeScript и production-сборка |

## API

Все прикладные методы, кроме `/api/health` и `/api/auth/*`, требуют сессионную cookie.

| Метод | Адрес | Назначение |
| --- | --- | --- |
| `POST` | `/api/auth/login` | Вход |
| `GET` | `/api/auth/session` | Текущая сессия |
| `POST` | `/api/auth/logout` | Выход |
| `GET` | `/api/tasks?date=YYYY-MM-DD` | Задачи на день |
| `POST` | `/api/tasks` | Создать задачу |
| `PATCH` | `/api/tasks/:id` | Изменить задачу или статус |
| `DELETE` | `/api/tasks/:id` | Удалить задачу |
| `GET` | `/api/wiki` | Список документов wiki |
| `GET` | `/api/wiki/:id` | Один документ wiki |
| `POST` | `/api/wiki` | Создать документ wiki |
| `PATCH` | `/api/wiki/:id` | Изменить документ wiki |
| `DELETE` | `/api/wiki/:id` | Удалить документ wiki |
| `GET` | `/api/passwords` | Доступы без значений паролей |
| `POST` | `/api/passwords` | Создать доступ |
| `PATCH` | `/api/passwords/:id` | Изменить доступ |
| `POST` | `/api/passwords/:id/reveal` | Получить расшифрованный пароль |
| `DELETE` | `/api/passwords/:id` | Удалить доступ |
| `GET` | `/api/health` | Проверка сервера |

Подробности: [архитектура](docs/architecture.md), [правила разработки](AGENTS.md).
