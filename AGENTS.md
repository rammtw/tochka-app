# AGENTS.md

## Назначение проекта

«Точка» — локальное однопользовательское приложение с ежедневным трекером задач, текстовой базой знаний и отдельным хранилищем зашифрованных паролей. Клиент: React, TypeScript, Vite, React Router. Сервер: Node.js, Express, встроенный `node:sqlite`.

## Команды

```bash
npm install          # установка зависимостей
npm run dev          # Vite :5173 и API :3001
npm run typecheck    # строгая проверка клиентского TypeScript
npm run build        # typecheck + production build в dist/
npm start            # production-сервер после npm run build
```

Node.js должен быть версии 22.5 или новее. Не заменяйте `node:sqlite` на native-зависимость без причины.

## Архитектурные правила

- Клиент использует FSD v2.1: `app → pages → shared`. Импорты только вниз по слоям.
- Не создавайте `entities`, `features` или `widgets` заранее. Сначала держите код в странице-владельце; выделяйте слой после подтверждённого повторного использования и появления самостоятельной ответственности.
- Каждая страница (`tasks`, `wiki`, `passwords`) и shared-компонент экспортируются через свой `index.ts`. Не импортируйте внутренние файлы чужого slice.
- Wiki и хранилище паролей — независимые разделы с отдельными DTO, состоянием, API и таблицами. Не возвращайте поля паролей в wiki.
- `shared` не содержит продуктовых правил. CRUD страницы с одним потребителем остаётся в `pages/<page>/api`.
- Именуйте файлы по предметной области, а не общими `utils.ts` или `types.ts`.
- Серверные роуты не возвращают сырые строки БД: преобразуйте snake_case в публичные camelCase DTO.

## Инварианты данных

- Дата задачи — строка локального календарного дня `YYYY-MM-DD`, время — `HH:MM`. Не переводите календарную дату в UTC.
- Проверяйте и нормализуйте все входные данные в `server/validation.js`; используйте параметризованные SQL-запросы.
- Пароли нельзя хранить открытым текстом, логировать или включать в `GET /api/passwords` и обычные CRUD-ответы.
- Изменение секретов выполняется только через `server/secrets.js`. Показ значения идёт через отдельный endpoint `/api/passwords/:id/reveal`.
- На клиенте пароль по умолчанию скрыт. После редактирования или удаления записи очищайте расшифрованное значение из состояния.
- Миграция старых секретов из `wiki_entries` в `password_entries` должна оставаться транзакционной и идемпотентной.
- Не коммитьте `data/`, `.env`, SQLite-файлы или ключи. При изменении формата шифрования предусмотрите версию envelope и миграцию.

## Стиль изменений

- Следуйте существующим TypeScript/JavaScript и CSS-конвенциям; не добавляйте состояние-менеджер, ORM или UI-библиотеку без необходимости.
- Пользовательский текст выводите только как текст React. Не используйте `dangerouslySetInnerHTML` для заметок.
- Markdown wiki отображайте через `MarkdownView` (`react-markdown` + `remark-gfm`). Не включайте `rehype-raw` или выполнение встроенного HTML.
- Сохраняйте доступность: подписи полей, русские `aria-label` для icon-only кнопок, видимый focus, закрытие модальных окон по Escape.
- При изменении API обновите README и `docs/architecture.md`; при изменении правил разработки обновите этот файл.
- Перед завершением запустите `npm run build` и проверьте затронутый пользовательский сценарий через реальный API или интерфейс.
